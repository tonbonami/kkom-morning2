# Aside 의뢰서 — 동시 감수: 꼼톡(꼼모닝) vs 사이챗(사이담) 이모티콘 흐름 나란히 비교

> 꼼모닝 세션(Claude Code)이 Aside CLI로 보낸다(2026-10-28). 우댕 지시: "aside에 검수 넘길 준비해. 이번에는 동시 감수야."
> **이 글 전체가 지시다. 파일을 따로 열지 않는다. 이번 의뢰만 한다**(예전 대화에 남은 다른 지시는 하지 않는다).

## 🚨 멈춤·금지 (두 앱 공통)
- **PIN·비밀번호·로그인 화면이 나오면 즉시 멈추고 보고.** 아무것도 입력하지 않는다.
- 각 앱 화면 위의 **「연습 모드」 띠가 안 보이면 즉시 멈추고 보고**(그 상태에선 메시지가 진짜 간다).
  꼼모닝은 **노란 띠**, 사이담은 **어두운 띠(#2B2730) 안에 노란 글씨(#FFE9A8)** 「연습 모드 — 상대에게 아무것도 안 가요」다.
- 결제·구매·충전·설정 변경·공개·공유·초대 금지. ★ 즐겨찾기는 **B(사이담)에서만** 눌러도 된다(연습 자리에 따로 쌓여 우댕 것과 안 섞인다). **A(꼼모닝)에서는 계속 금지**(우댕의 진짜 목록이 바뀐다).
- **꼼모닝(A)**: 홈 화면에선 「꼼톡」 단추만 누른다. **홈의 하트·범프·기분·선물·퀵메시지·편지·칭찬·낙서장·꿀닥터 단추는 절대 누르지 않는다**(연습 모드로도 안 막혀서 꼼이에게 진짜 간다). 꼼톡 화면 안에서만 움직인다.
- **사이담(B)**: **주어진 방 하나(「민준」) 안에서만 움직인다.** 다른 방으로 옮기거나 새 방을 만들지 않는다. **다른 계정으로 로그인하지 않는다.** **방 나가기·계정 삭제·탈퇴·차단·신고·비밀번호 변경·이름/방 설정 변경 금지.** **이모티콘 팩 실제 구매 금지**(결제는 연습 모드가 막지 못한다). 사이담은 홈 하트·범프·기분·선물도 연습 모드에 걸린다. 다만 **띠가 안 보이면 그 보장이 없으니 즉시 멈춘다.**

## 목적
우댕이 원한 것(아래 (가)~(라))을 기준으로, **두 앱이 같은 입력에 어떻게 다르게 보이고 움직이는지**를 단계마다 나란히 찍어 적는다. 어느 쪽이 맞다고 미리 정하지 말고 **본 그대로** 적는다.
- (가) 칠 때 큰 추천 줄은 안 뜨고, 입력줄 오른쪽 ☺ 자리에 그 낱말의 **작은 이모티콘 하나**.
- (나) 그걸 누르면 **그 낱말로 찾은 이모티콘창**이 열린다.
- (다) 이모티콘창에서 누르면 **대화 위 반투명 카드**(★·✕)로 떠서 확인, **전송 단추**로 보낸다.
- (라) 「사랑해」만 쳤으면 글자는 **사라지고**(이모티콘이 대신), 「내사랑 꼼슌이 보고싶어」처럼 **문장이면 글이 하나도 안 지워지고** 이모티콘과 함께 간다.
- 그리고 이모티콘창의 **「최근 사용」·「자주 쓰는」** 칸 구성(우댕: "꼼모닝의 최근사용 자주사용도 베끼란 말이야").

## 준비
- 브라우저 창 둘(또는 탭 둘을 나란히)을 **같은 폰 폭**(가능하면 390×844, 안 되면 둘 다 같은 폭)으로 맞춘다. 실제 쓴 폭을 보고에 적는다.
- **A 꼼모닝**: `https://kkommorning-v2.vercel.app/?practice=1` → 강력 새로고침 → 「꼼톡」. 이 브라우저엔 우댕 계정으로 이미 들어가 있다(오늘 1·2차 검수와 같다). 연습 모드에선 보내기·입력 중·읽음·접속 표시가 막혀 꼼이 화면엔 아무것도 안 남는다.
- **B 사이담**: `https://saidam.vercel.app/?practice=1` → 강력 새로고침. 이 브라우저엔 시험 계정(`aside.a@saidam.test`)으로 **이미 들어가 있다. 로그인·비밀번호 화면이 나오면 아무것도 입력하지 말고 즉시 멈추고 보고.** 방은 **「민준」 하나뿐**(상대는 시험용이라 답하지 않는다). 화면 맨 위 띠를 먼저 확인한다 — 어두운 띠 안 노란 글씨 「연습 모드 — 상대에게 아무것도 안 가요」. 막힌 동작을 누르면 2.2초 동안 「연습 모드 — 「…」 안 보냈어요」로 바뀐다.
- 두 쪽 다 시작할 때 입력칸을 비운다.

## 단계 — 단계마다 **A·B 화면을 하나씩** 찍어 artifacts에 `S1_A.png`, `S1_B.png` 식으로 저장
가능하면 눈대중이 아니라 **요소 크기(px)**를 재서 적는다(입력줄 그림·단추, 이모티콘창 탭 줄·칸 크기, 미리보기 카드).

| # | 두 앱에 똑같이 할 것 | 비교해서 적을 것 |
|---|---|---|
| S1 | 입력칸 빈 채로 | 입력줄 안 요소 순서(왼→오)·☺ 단추 크기 |
| S2 | 「사랑해」 입력 | ☺ 자리가 작은 그림으로 바뀌는지·크기·튀어나오는 움직임 · **입력줄 위에 큰 추천 줄이 뜨는지** |
| S3 | 그 작은 그림을 누름 | 이모티콘창 구성: 탭 줄(무엇이 어떤 순서)·검색칸 글자·결과 격자(열 수·칸 크기)·글 속 미니 칸 따로인지·분홍 안내 문구 · 키보드/⌨ 단추 |
| S4 | 이모티콘창 검색칸을 지우고(✕) 첫 탭(최근·자주) | **「★ 즐겨찾기」·「자주 쓰는」·「🕒 최근 사용」 칸**: 있는지·순서·모양(가로 줄/격자)·칸 크기·개수·빈 경우 안내 글 |
| S5 | 다시 「사랑해」 → 작은 그림 → 결과 첫 번째(미니 아닌 것) 누름 | 미리보기 카드: 자리(대화 위? 서랍 위?)·반투명 정도·★✕ 위치·카드 아래 글 · **입력칸 「사랑해」가 지워졌는지** |
| S6 | 미리보기 ✕ | 「사랑해」가 입력칸에 돌아오는지 · 서랍은 열린 채인지 |
| S7 | 다시 하나 골라 **보내기** | 연습 모드 알림 문구 · 보낸 뒤 서랍·검색칸·입력칸 상태 |
| S8 | 입력칸 비우고 「내사랑 꼼슌이 보고싶어」 → 작은 그림 → 하나 고름 | **입력칸 글이 그대로인지** · 카드 아래 글 · 그다음 보내기를 누르면 연습 모드 알림이 「글+이모티콘 한 통」인지 「두 통」인지(알림 문구 그대로 옮겨 적기) |
| S9 | 「사랑해~~」, 「배고파 ㅠㅠ」 각각 → 작은 그림 → 하나 고름 → ✕ | 글이 지워지는지(꾸밈 처리) · ✕로 원래 글(꾸밈 포함)이 돌아오는지 |
| S10 | 이모티콘창이 열린 채 입력칸을 누름 | 이모티콘창이 닫히고 키보드로 가는지 · ⌨/☺ 단추 바뀜 |
| S11 | 대화 빈 곳을 한 번 누름 | 이모티콘창 닫힘 · 미리보기가 있었다면 남는지 |
| S12 | 이모티콘창을 다시 열어 첫 탭(최근·자주). **B에서만** 아무 칸 2개를 꾹(0.5초) 눌러 ★ 담기 → 다시 봄 | S5~S9에서 고른 것이 「🕒 최근 사용」에 쌓였는지(A는 연습 모드라 안 쌓이는 게 정상 — 원래 있던 목록이 그대로인지만) · B의 「★ 즐겨찾기」·「자주 쓰는」·「🕒 최근 사용」 순서·모양·칸 크기(px)를 S4의 A와 나란히 |

끝나면 두 쪽 입력칸을 비우고 채팅을 닫는다.

## 보고 형식

    S1 … S12: 같음 / 다름 — 다르면 「A는 …, B는 …」 한 줄(크기 px가 있으면 같이)
    (S4에서 B가 「아직 쓴 이모티콘이 없어요」면 시험 계정이 처음이라 그렇다 — 빈 화면 문구만 비교하고, 칸 구성은 S12에서 비교한다)
    화면: (artifacts 파일 이름들)
    [다른 점 순위] 쓰는 사람이 바로 느끼는 것부터 5개까지 — 각각 (가)~(라) 중 어디에 해당하는지, 어느 쪽이 (가)~(라)에 더 맞는지
    [의견] 두 앱 공통으로 아직 불편한 점 3개까지

※ 이미 알려진 의도된 차이 하나: 사이담은 말풍선 구조상 **글이 남아 있으면 글과 이모티콘을 두 통으로** 보낸다(꼼모닝은 한 통). 이건 「다름」으로 적되 「알려진 차이」라고 표시한다.
