안녕, 또 Claude야. 커플 채팅 앱 「꼼모닝」의 채팅창(꼼톡) 이모티콘 서랍 배치 회의야. 파일은 열지 말고 이 글만 보고 답해 줘. 코드는 짧은 핵심만.

## 사용자(우댕)의 불만 (원문 그대로)
「카톡과 비교해봐. 우리 앱 헷갈려. 이모티콘 추천 누르면 채팅 입력하는게 밑으로 내려가 위에 추천 문구랑 같이 섞여서 어디다가 타이핑 할까 순간 헷갈려.」
(우댕이 꼼톡 화면과 카톡 화면을 나란히 찍어 보여 줬다. 사진엔 사적인 대화가 있어서 글로만 옮긴다.)

## 지금 꼼톡 (입력칸에 「배고파요 사랑해」를 치고 → 입력줄 오른쪽 작은 이모티콘 단추를 누른 상태), 화면 위→아래
1. 대화 말풍선들
2. (고르면) 반투명 미리보기 카드 — 서랍 바로 위에 뜸
3. **이모티콘 서랍(흰 둥근 카드)** — 맨 위에 **흰 둥근 검색칸**(돋보기 + 「사랑해」 + ✕, 높이 40px, 글씨 16px) → 「찾은 이모티콘 5개 / 고르면 입력한 글과 함께 가요」 → 4열 결과 격자 → 「글 속 미니」 칸. 검색어가 없을 땐 이 자리에 탭 줄(최근·자주, 캐릭터별 그림 탭)과 격자.
4. **입력줄** — ＋ / 「배고파요 사랑해」 / ⌨(키보드로) 단추 / 보내기. 서랍이 열리면 키보드는 내려가고 입력줄은 화면 맨 아래로 간다.
→ 서랍 안 검색칸과 맨 아래 입력줄이 **똑같이 흰 둥근 글칸**이라, 둘 다 「글 쓰는 곳」처럼 보인다. 입력줄이 서랍 아래로 밀려 내려가 위치도 바뀐다.

## 카톡 (같은 상황), 화면 위→아래
1. 대화 말풍선들
2. 반투명 미리보기 카드(★·✕) — 대화 위에 떠 있음
3. **입력줄** — ＋ / 「배고파요 <u>사랑해</u>」(찾은 낱말에 파란 밑줄) / ⌨ / 보내기. **키보드가 있던 높이 그대로** 있다.
4. **이모티콘 서랍** — 입력줄 **아래**, 키보드 자리(높이 ≈ 키보드). 맨 위 손잡이 → 큰 탭 「검색 / 이모티콘 / 미니 / 발견」 → **검색어는 글칸이 아니라 알약 단추**: 「〈🔍」(검색 다시) · 「사랑해」 · 「큰하트」 → 결과 격자.
→ 글 쓰는 곳은 입력줄 하나뿐. 서랍은 키보드처럼 아래에서 올라온다.

## 앱 구조
- iOS 앱이지만 화면은 웹(Next.js + React, WKWebView). 키보드가 뜨면 `visualViewport`로 키보드 높이를 재서 입력줄 아래 여백으로 준다(화면 높이는 고정). 웹에서는 키보드 높이를 키보드가 뜬 뒤에야 알 수 있다.
- 서랍을 열면 입력칸 focus를 빼서(blur) 키보드를 내린다. ⌨ 단추로 서랍 닫고 키보드로.

## 부탁
1. 카톡처럼 **서랍을 입력줄 아래(키보드 자리)**로 옮기는 게 맞는지, 그때 **서랍 높이**를 어떻게 정할지(마지막 키보드 높이 기억? 고정 비율? 처음엔 키보드 높이를 모름) 와 **키보드 ↔ 서랍 전환 때 입력줄이 덜컹거리지 않게** 하는 법.
2. **서랍 안 검색칸**을 어떻게 바꿀지 — 알약 단추(카톡식) / 탭 「검색」 안에서만 글칸 / 기타. 사용자가 다른 말로 직접 찾고 싶을 때(지금은 검색칸에 직접 친다)의 동선도.
3. 입력줄 안의 찾은 낱말 표시(카톡의 파란 밑줄) — 넣을 가치가 있는지, 웹 `<textarea>`에서 어떻게(덧그리기 등).
4. 미리보기 카드 자리 — 서랍이 아래로 가면 카드는 입력줄 위(대화 위)에 뜨는 게 맞는지.
5. 바꾸면서 생길 함정(아이폰 웹뷰 키보드·안전 영역·스크롤·서랍 열린 채 입력칸을 누를 때 등)과 대처.
6. **꼭 바꿀 것 / 나중에 해도 될 것**을 순서대로 짧게.

한국어로, 항목 번호대로, 짧고 분명하게 답해 줘. 모르는 건 「확인 필요」라고 적어 줘.
