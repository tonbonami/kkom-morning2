# Aside 의뢰서 — 꼼모닝 채팅(꼼톡) 입력 검수

> Teo 먼저 읽기 (⚠️ 개인정보·부작용 — 맡길지 Teo가 판단)
> - Aside가 **우댕 계정으로 로그인**하면 두 사람의 실제 대화가 외부 브라우저를 지나간다.
> - 채팅창을 **여는 것만으로** 실데이터가 바뀐다: 꼼이 메시지가 **읽음**으로 바뀌고, 꼼이 화면에 우댕이 **"지금 함께"(접속 중)**로 뜬다. 꼼이도 앱을 켜 둔 상태면 **꼼이 쪽 채팅창이 자동으로 열린다.**
>   → 꼼이가 앱을 안 쓰는 시간에 돌리거나, 꼼이에게 미리 말해 두기.
> - 로그인 코드는 이 문서에 쓰지 않는다. Aside Vault 자동 채우기로.

---

## 너의 역할

너는 **이 커플 앱을 오늘 처음 받은 사람**이다. 애인이 "우리 둘만 쓰는 앱이야, 여기서 톡해" 하고 깔아 줬다. 카카오톡은 매일 쓴다.
동시에 너는 **모바일 웹 입력 UX를 아는 검수자**다. 코드는 모른다고 생각하고, 화면에서 본 것만 말한다.

## 🚨 절대 금지 (어기면 되돌릴 수 없다 — 상대에게 실제로 간다)

- **메시지·사진·이모티콘·하트·선물·음성·타임캡슐을 보내지 마라.** 보내기 버튼, 이모티콘 그림, 추천 이모티콘 그림을 **누르지 마라** (이모티콘 그림은 누르는 순간 바로 전송된다).
- **채팅 입력칸에 글자를 치지 마라.** 컴퓨터에선 Enter가 곧 전송이고, 글자를 치는 동안 상대 화면에 "입력 중…"이 뜬다. 입력칸은 **클릭해서 포커스만** 한다.
- 메시지를 길게 누르기/우클릭해서 나오는 **삭제·수정·저장(책갈피)** 을 누르지 마라.
- 이미지를 끌어다 놓거나 붙여 넣어 "이 사진을 보낼까요?"가 뜨면 **반드시 '취소'**. '보내기' 금지.
- 테마 바꾸기, 로그아웃, 설정 변경 금지. 홈 화면의 하트·범프·기분·선물 버튼도 누르지 마라.
- **열어 보는 것(패널·서랍·모달 열기)까지만** 한다. 확정·발송·저장·삭제는 0번.

## 할 일

### A. 입력줄 (가장 중요)
1. 채팅을 열고 **입력칸을 클릭**한다. 입력칸이 **화면 안에 다 보이는지**, 아래에 쓸모없는 빈칸이 있는지, 무엇이 입력칸을 가리는지 기록.
2. ＋ 를 열었다 닫는다. ☺ 를 열었다 닫는다. 각각 **입력칸이 위로 밀리나/가려지나/메시지가 몇 줄 가려지나** 기록.
3. 휴대폰 폭에서 **화면 키보드(가상 키보드)를 띄울 수 있으면** 띄워서 1·2를 반복. **못 띄우면 "못 봄"** 이라고 적는다.

### B. 처음 쓰는 사람의 눈 (발견 가능성)
안내 없이 다음을 **어떻게 할지 찾기만** 한다 (실행 금지, 버튼 위치 확인까지):
사진 보내기 / 이모티콘 보내기 / 음성 보내기 / 타임캡슐(미래에 도착하는 메시지) / 답장하기 / 지난 대화 모아보기.
각각 **몇 번 눌러서 찾았나, 어디서 헤맸나, 화면 글자 그대로** 기록. 못 찾으면 "못 찾음".

### C. 내 진단·수정안 반박 (아래 부록)
부록의 진단과 수정안을 읽고 **틀린 곳, 빠진 위험, 더 나은 방법**을 찾아라. 웹에서 같은 사례(아이폰 WebKit·Capacitor 키보드)를 찾으면 **주소와 함께** 적어라. 여기만 의견을 허용하되, 의견은 `[의견]`으로 표시하고 근거 주소를 붙인다.

## 기록 규칙

- **본 것만 적어라. 못 본 건 "못 봄"이라고 적어라. 추측 금지.** (C의 `[의견]`만 예외)

## 부록 — 아이폰 앱에서 키보드가 입력칸을 가리는 버그 (C용)

### 증상
- 아이폰 앱(TestFlight 빌드 54 이후, iOS 26)에서 채팅 입력칸을 누르면 **키보드가 입력칸 아래쪽 절반 이상을 덮는다.** 입력칸 윗부분만 키보드 위로 빼꼼 보인다.
- **빌드 53까지는 괜찮았다.** 그땐 키보드 위에 `^ ∨ ✓`(이전 칸·다음 칸·완료) 막대가 있었고, 입력칸은 그 막대 바로 위에 온전히 보였다.

### 빌드 54에서 바꾼 것
그 `^ ∨ ✓` 막대가 거슬린다고 해서 앱 네이티브 코드에서 막대를 없앴다. 웹 입력칸에 포커스가 가면 WebKit이 `WKContentView.inputAccessoryView`로 이 막대를 붙이는데, 그 값을 nil로 바꿨다:

```swift
// ios/App/App/MainViewController.swift — capacitorDidLoad()에서 한 번 호출
enum FormAccessoryBar {
    private static var applied = false
    static func hide() {
        guard !applied, let cls = NSClassFromString("WKContentView") else { return }
        let sel = #selector(getter: UIResponder.inputAccessoryView)
        guard let method = class_getInstanceMethod(cls, sel) else { return }
        let none: @convention(block) (AnyObject) -> UIView? = { _ in nil }
        class_replaceMethod(cls, sel, imp_implementationWithBlock(none), method_getTypeEncoding(method))
        applied = true
    }
}
```
공식 `@capacitor/keyboard` 플러그인도 같은 방식으로 막대를 숨기지만, 그 플러그인은 **키보드가 뜰 때 웹뷰 크기를 줄이는 동작(resize)** 까지 같이 바꾼다. 채팅 입력창 위치가 흔들릴까 봐 플러그인은 안 쓰고 막대 끄는 부분만 가져왔다.

### 채팅 화면 구조 (키보드 대응 코드 없음)
```tsx
// src/components/ChatPanel.tsx — 채팅 전체
<motion.div className="fixed inset-0 z-[60] flex flex-col" drag="x" ...>   // 화면 전체 고정
  <header .../>                                  // 위: 상대 이름·아이콘
  <div className="flex-1 overflow-y-auto">…메시지…</div>
  <div className="px-3 pt-2 border-t"
       style={{ paddingBottom: 'max(env(safe-area-inset-bottom), 1.25rem)' }}>  // 아래: 안전영역 여백(약 34pt)
    <div className="flex items-end gap-1 rounded-[26px] p-1.5 …">            // 둥근 입력줄
      <button>＋</button><textarea rows={1} …/><button>☺</button>
    </div>
  </div>
</motion.div>
```
- 키보드가 뜰 때 화면 높이를 맞추는 코드가 **하나도 없다.** WebKit이 "포커스된 입력칸이 보이게" 화면을 알아서 밀어 올려 주는 것에만 기대고 있다.
- 앱은 Capacitor 6, `ios.contentInset: 'always'`, 웹은 Vercel 배포본을 그대로 띄운다.

### 내 진단 (가설 — 아직 시뮬레이터로 확정 전)
1. 막대가 있을 때 WebKit은 "키보드 + 막대" 높이만큼 밀어 올렸고, 입력칸이 그 위에 딱 맞았다.
2. 막대를 없애자 **입력칸이 막대 높이(약 60pt)만큼 덜 올라온다.** 사용자 스크린샷 두 장에서 가려진 양이 막대 높이와 거의 같다.
3. 즉 화면을 키보드에 맞추는 일을 WebKit의 자동 스크롤에만 맡긴 게 근본 원인이고, 막대 제거가 그 약점을 드러냈다.
4. 덤: 키보드가 떠 있을 때도 아래 **안전영역 여백(약 34pt)** 이 그대로 남아 입력칸과 키보드 사이가 뜬다. 카톡엔 이 틈이 없다.

### 수정안 (내 추천 순)
1. **웹에서 해결 (추천).** 채팅이 열려 있는 동안 `visualViewport`의 `resize`·`scroll`을 듣고, 채팅 전체(`fixed`)의 `height = visualViewport.height`, `top = visualViewport.offsetTop`으로 맞춘다. 입력칸이 항상 키보드 바로 위에 붙는다. 키보드가 떠 있으면 아래 안전영역 여백도 줄인다. 웹 배포만으로 반영(앱 새 빌드 불필요), 사파리에서도 좋아진다.
2. **네이티브에서 해결.** 키보드가 뜰 때(`keyboardWillShow`) 웹뷰 높이를 키보드만큼 줄인다(플러그인의 resize와 같은 방식). 앱 새 빌드 필요, 앱의 모든 화면에 영향.
3. **되돌리기.** 막대 제거를 취소한다 → 입력칸은 다시 보이지만 `^ ∨ ✓` 막대가 돌아온다.

### C에서 특히 따져 줄 것
- 1번의 위험: WebKit이 자기 식으로 또 밀어 올려서 **두 번 올라가는 것**, 키보드 올라오는 애니메이션 중 **덜컥거림**, 채팅 패널의 좌우 스와이프(닫기)와 충돌, 키보드가 바뀔 때(한글↔이모지·받아쓰기) 높이 재계산.
- 내 진단 2번(막대 높이만큼 덜 올라온다)이 맞을 법한지. 다른 원인 후보가 있으면.
- 아이폰 WebKit + `visualViewport`로 채팅 입력칸을 붙이는 실제 사례·함정(주소 포함).
