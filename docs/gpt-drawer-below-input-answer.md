우댕 불만이 맞아요. 핵심 문제는 검색 기능보다 **입력줄의 위치가 바뀌고, 글칸처럼 보이는 요소가 두 개 생기는 것**입니다.

1. 서랍 위치·높이·전환

- **서랍을 입력줄 아래, 기존 키보드 자리로 옮기는 게 맞습니다.**
- 입력줄은 항상 같은 Y 위치에 두고, 아래 영역만 `키보드 ↔ 서랍`로 교체하세요.
- 서랍 높이는 우선순위대로 정합니다.
  1. 현재 세션에서 측정한 마지막 키보드 높이
  2. 아직 측정 전이면 화면 높이의 `38%`
  3. 최소·최대 제한: 예시 `280px ~ 360px`
- 첫 실행부터 정확한 키보드 높이를 아는 것은 불가능합니다. **기기별 영구 저장보다 현재 세션의 실측값 기억**이 안전합니다.
- 전환할 때는 키보드가 완전히 내려간 뒤 서랍을 붙이지 말고, 입력줄 아래 공간을 마지막 높이로 먼저 고정한 뒤 내용만 바꾸세요.

```css
.composerArea {
  padding-bottom: var(--bottom-panel-height);
}
.bottomPanel {
  height: var(--bottom-panel-height);
}
```

- 키보드 높이가 새로 측정되면 패널 높이만 갱신하되, 입력줄 위치는 유지합니다.
- `visualViewport` 값이 여러 번 튈 수 있으므로 약 `100~150ms` 안정화 후 확정하는 편이 좋습니다.

2. 서랍 안 검색칸

- 기본 화면에서는 **글칸을 없애고 알약 형태의 검색어 표시**로 바꾸는 것을 추천합니다.
- 예: `🔍 다시 찾기` · `사랑해` · `큰하트`
- 알약은 흰 입력칸처럼 만들지 말고 회색 배경, 작은 높이, 명확한 버튼 모양으로 구분하세요.
- 다른 말로 찾고 싶을 때:
  1. `🔍 다시 찾기`를 누름
  2. 서랍의 `검색` 탭으로 이동
  3. 그때만 검색 글칸을 보여 주고 자동 포커스
  4. 키보드가 뜨면 서랍 대신 키보드가 아래 영역을 차지
  5. 검색 확정 후 키보드를 내리고 결과 서랍으로 복귀
- 검색 탭 안에 항상 글칸을 두는 방식도 가능하지만, 기본 결과 화면에서는 숨기는 게 덜 헷갈립니다.
- 지금처럼 입력 문장에서 자동 추출된 검색어와 사용자가 직접 입력하는 검색어는 상태를 분리해야 합니다.

3. 찾은 낱말 표시

- **넣을 가치가 있습니다.** 어떤 말 때문에 이 결과가 나왔는지 바로 이해되고, 이모티콘과 원문이 함께 전송된다는 것도 예측하기 쉬워집니다.
- 다만 1차 필수 수정은 아닙니다.
- `<textarea>` 안에서 일부 글자만 꾸미기는 어렵습니다. 뒤에 같은 글을 그리는 오버레이를 두고, 실제 textarea 글자는 투명하게 만드는 방식이 일반적입니다.

```jsx
<div className="inputWrap">
  <div className="highlight" aria-hidden>{renderHighlighted(text)}</div>
  <textarea value={text} />
</div>
```

- 두 레이어의 글꼴, 줄높이, 패딩, 줄바꿈, 스크롤 위치를 완전히 맞춰야 합니다.
- 한글 조합 중에는 강조 계산을 멈추고 `compositionend` 뒤 갱신하세요.
- 구현 복잡도가 부담되면 1차에는 입력줄 위에 작은 `“사랑해”로 찾는 중` 표시만 넣어도 됩니다.

4. 미리보기 카드 자리

- **입력줄 바로 위, 대화 영역 위에 떠 있는 배치가 맞습니다.**
- 서랍 내부에 넣지 말고 입력줄에 붙은 떠 있는 레이어로 취급하세요.
- 대화를 밀어 올리기보다 겹쳐 띄우되, 마지막 말풍선이 가려지지 않도록 대화 영역의 아래 여백을 확보합니다.
- 선택 해제·닫기 버튼은 카드 안에 계속 보여 주세요.

5. 예상 함정과 대처

- `visualViewport` 값이 키보드 애니메이션 중 흔들림  
  → 여러 이벤트 중 안정된 마지막 값을 사용하고 높이 변화에 제한을 둡니다.
- `blur`와 서랍 열기가 겹치며 화면이 한 번 내려갔다 올라옴  
  → 먼저 아래 패널 높이를 고정하고 다음 프레임에 `blur`와 서랍 전환을 실행합니다.
- 서랍이 열린 채 입력칸을 누름  
  → 서랍을 닫고 입력칸에 포커스한 뒤, 키보드 실측 높이로 패널 값을 갱신합니다.
- 안전 영역이 키보드·서랍 높이에 중복 포함됨  
  → `env(safe-area-inset-bottom)`을 누가 담당하는지 하나로 통일합니다. 키보드가 열린 상태에서 실제 포함 여부는 **확인 필요**입니다.
- 키보드 전환 때 대화 스크롤 위치가 튐  
  → 전환 전 “맨 아래에 있었는지” 기록하고, 맨 아래였을 때만 전환 후 다시 아래에 붙입니다.
- 입력 중 한글 조합이 끊김  
  → 이모티콘 단추를 눌렀을 때 조합 확정 여부와 `blur` 순서를 실기기에서 확인해야 합니다.
- 서랍 내부 스크롤이 전체 화면 드래그로 전달됨  
  → 서랍만 독립 스크롤시키고 `overscroll-behavior`를 적용합니다.
- iPhone 기종·iOS·서드파티 키보드별 높이 차이  
  → 고정값 하나에 의존하지 말고 실측값을 우선합니다. WKWebView별 실제 동작은 **확인 필요**입니다.

6. 적용 순서

**꼭 바꿀 것**

1. 입력줄을 고정하고 서랍을 그 아래로 이동
2. 마지막 키보드 높이 기반으로 아래 패널 공간 유지
3. 기본 결과 화면의 검색 글칸 제거
4. 검색어 알약과 `다시 찾기` 동선 추가
5. 미리보기 카드를 입력줄 위로 이동
6. 키보드·서랍 전환과 대화 스크롤을 실제 아이폰에서 재검수

**나중에 해도 될 것**

7. 입력줄의 검색 낱말 밑줄 오버레이
8. `검색·이모티콘·미니·발견` 같은 큰 탭 구조 확장
9. 키보드 높이의 기기별 영구 저장
10. 전환 애니메이션과 미세한 시각 효과 조정
