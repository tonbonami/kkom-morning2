# 사이챗 — 이모티콘 서랍을 입력줄 아래로 + 보낸 말이 입력줄에 가려지는 것 (꼼모닝 → 사이담, 2026-11-04)

우댕님 요청: 「꼼톡처럼 채팅 입력창이 이모티콘보다 위로 가게. 사이담은 아직 반대야. 그리고 메시지 보내면 입력창에 가려져서 보낸 메시지가 안 보여. 똑같이 고치게 하고 싶은데, 전에 고치다 엄청 깜빡거린 적이 있으니 조심하라고 해줘.」

꼼모닝 세션이 두 저장소 코드를 나란히 읽고 정리했다. **사이담 코드는 안 고쳤다.** 줄 번호는 2026-11-04 기준(사이담 `de18440`, 꼼모닝 `70afbe2`).

## 2. 「보낸 말이 입력줄에 가려진다」 — 원인 추정

목록과 입력줄은 flex 형제라 **겹치지 않는다**(`main.flex-col.h-app` → 목록 `flex-1 min-h-0` → 입력줄). 가려진다는 건 **바닥으로 내린 뒤 목록 안 내용이 더 길어졌는데 다시 안 내렸다**는 뜻이다.

- **이모티콘 그림은 높이를 미리 안 잡는다** — 1273 `<img className="max-h-[138px] max-w-[150px] …">`. 보내면 `msgs.length` 효과가 바닥으로 내리고(그림은 아직 0px), **그다음 그림이 실리면서 최대 138px 길어진다.** 목록 **상자** 크기는 그대로라 `ResizeObserver` 가 안 울리고, `load` 를 안 들으니 아무도 다시 안 내린다 → 방금 보낸 이모티콘이 입력줄 뒤로.
- 같은 모양: 링크 미리보기(`ChatLinkPreview`, 늦게 뜸), 사진, 서버 시각이 확정된 뒤 붙는 시간·읽음 표시(길이는 그대로라 `msgs.length` 효과가 다시 안 돈다).
- ⚠️ **실기기에서 재현해 확인하지는 않았다.** 고치기 전에 보내고 나서 0·300·1000ms 에 `list.scrollHeight − list.scrollTop − list.clientHeight` 를 찍어 보면 바로 갈린다(늘어나면 이 원인).

### 고칠 것 (꼼톡과 같게)
1. 595~631 효과에 **`list.addEventListener('load', onLoad, true)`**(캡처 — img·video 로드는 버블링 안 한다) — `onLoad = () => { if (stickRef.current) stickToBottom(); }`. 정리 때 `removeEventListener(…, true)`.
2. 566~569 를 **`msgs` 전체**(또는 마지막 메시지 id + 그 상태)에 걸고, 즉시 한 번 + `requestAnimationFrame` 뒤 한 번. 꼼톡 1227~1232 참고.
3. **내가 보낼 때는 `stickRef.current = true`** — 올려 읽던 중이어도 내가 보낸 말은 봐야 한다.

## 3. 서랍을 입력줄 아래로 — 사이챗에서 바꿀 자리

꼼톡 커밋 `8162c5e` 가 같은 일을 했다(설명·GPT 상의 `docs/gpt-drawer-below-input-*.md`). 사이챗에 옮길 때:

1. **`panelH`** 상태 — 처음엔 `clamp(280, innerHeight × 0.38, 360)`. **`kbPad`(=covered) ≥ 120 이 된 뒤 150ms 동안 안 바뀌면** `clamp(220, kbPad, 480)` 로. 꼼톡 1288~1294.
   - ⚠️ 꼼톡의 `kbInset` 식을 **가져오지 말 것.** 사이담 `useKeyboardViewport` 의 `covered`/`kbPad` 가 실기기에서 더 맞다(be0f790·fbba537·fd2a46e). 꼼톡에도 같은 구멍이 있다고 이미 알려 줬던 그 식이다.
2. **`holdPanel`** — 서랍이 열린 채 입력칸을 누를 때(2163 `onFocus`)와 ⌨ 단추(2192)에서 `true`. `kbOpen` 이 되면 바로, 아니면 700ms 뒤 `false`. 꼼톡 1296~1302, 2427, 2442.
3. **입력줄 바(`data-kb-bar`, 1542) 아래 여백** — `stickerOpen ? 0 : holdPanel ? panelH : kbOpen ? kbPad + 8 : 안전영역`. 서랍이 열려 있으면 서랍이 그 자리를 채우므로 0.
4. **서랍 블록(1571~)을 `data-kb-pill`(2129) 뒤로** 옮기고 바깥을 `height: panelH, paddingBottom: max(env(safe-area-inset-bottom), 8px)` 로 감싼다. 안쪽은 `flex h-full flex-col`, 스크롤 칸은 `max-h-[42vh]` 대신 `min-h-0 flex-1`. 탭 줄은 지금처럼 스크롤 밖.
5. **입력줄 위에 남는 것**: 고치는 중·답장·★ 토스트·이모티콘 미리보기(`StickerSendPreview`)·＋판. 미리보기는 입력줄 바로 위(대화 쪽)가 맞다(카톡과 같다).
6. ☺ 단추는 지금처럼 `blur()` 로 키보드를 내린다 — 키보드가 내려가는 동안 서랍이 같은 높이로 그 자리를 채워 입력줄이 안 움직인다.

꼼톡 개발 서버(375×812) 확인값: 입력줄 441~495 · 서랍 503~812 · 서랍→키보드 전환 중 입력줄 449 유지.

## 4. ⚠️⚠️ 깜빡임 — 사이담이 이미 두 번 겪은 것과, 이번에 새로 생길 수 있는 것

**이미 겪은 것(다시 만들지 말 것)**
- **`7ae269c` 광속 깜빡임** — `main` 높이를 `visualViewport.height` 로 줬더니 웹뷰가 그 값을 되돌려 알려 줘 812↔840 무한 반복(0.5초에 resize 15·렌더 36). → **화면 전체 높이는 절대 vv 로 쓰지 않는다.** 여백은 입력줄 바에만.
- **`d7ee0ba` 화면 떨림** — vv scroll 을 듣고 `offsetTop` 만큼 `translateY` → 그 이동이 다시 scroll → 무한. → **`translateY` 보정 금지**(지금은 `scrollTo(0,0)`).
- 같은 값이면 `setState` 안 함(`useKeyboardViewport` 80~82) — 서랍 쪽 새 상태에도 똑같이.

**이번에 새로 생길 수 있는 고리**
- **`panelH` 를 resize 마다 바로 바꾸지 말 것.** 키보드가 올라오는 동안 값이 여러 번 오는데, 그때마다 서랍 높이를 바꾸면 → 목록 높이 변화 → `ResizeObserver` → 바닥 붙이기 → … 가 프레임마다 돌아 **출렁인다.** 150ms 조용해진 뒤 **한 번만**, 그리고 값이 같으면 안 바꾼다. 키보드가 **내려가는 중**의 값으로는 안 바꾼다(≥120 일 때만, 타이머는 다음 값이 오면 취소).
- **`holdPanel` 은 반드시 풀려야 한다**(키보드 도착 또는 700ms). 안 풀리면 입력줄이 공중에 뜬 채 남는다.
- **바 여백과 서랍은 같은 렌더에서 같이 바뀌어야 한다** — 여백(kbPad → 0)과 서랍(없음 → panelH)이 한 번에 바뀌어야 입력줄이 제자리다. 한쪽만 먼저 바뀌면(예: 서랍은 다음 효과에서 열림) 한 프레임 튀었다 돌아온다 — 그게 「깜빡」으로 보인다. 둘 다 `stickerOpen`·`holdPanel` 한 상태에서 바로 계산할 것(따로 효과로 따라가게 하지 말 것).
- **`load` 리스너로 고리가 생기지 않는지** — 붙이기는 `scrollTop` 만 바꾸고 크기는 안 바꾸므로 `ResizeObserver` 가 다시 안 울린다. `stickToBottom` 이 세우는 `stickingRef` 를 그대로 쓸 것(직접 `scrollTop` 을 만지면 그 scroll 을 「사람이 올렸다」로 읽어 붙이기가 꺼진다 — 꼼톡·사이담 둘 다 겪음).

**확인 방법**
- 시뮬레이터 통과를 근거로 쓰지 말 것 — `fd2a46e` 처럼 실기기에서만 나는 것이 있다. **우댕님 폰에서 측정 창(KbReadout, `data-kb-pill` 재기)으로 확인한 뒤 배포.**
- 확인할 순서(꼼톡 검수 때 쓴 것): ① 서랍 열기 ② 서랍 → 입력칸 누르기(키보드로) ③ ⌨ 단추 ④ 이모티콘 보내기 → 방금 보낸 그림이 다 보이는지 ⑤ 긴 글 보내기 ⑥ 지난 대화 올려 읽다가 나갔다 다시 들어오기(7ae269c 재현 순서) — 매번 입력줄 알약 위치가 튀지 않는지, 화면이 떨리지 않는지.
- `scripts/check-chat-bottom.mjs` 가 새 구조(서랍 아래·holdPanel·load 리스너)를 지키게 넓힐 것 — 느슨하게 말고.
