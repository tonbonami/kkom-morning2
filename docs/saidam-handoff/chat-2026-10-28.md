## ① 「채팅창에 들어가면 화면이 아주 빠르게 깜빡임」 — 꼼모닝 기록

**솔직한 답: 꼼모닝엔 "들어가자마자 빠르게 깜빡임" 증상 보고·수정 기록이 없다.** `git log --grep 깜빡`을 다 봤다. 그래서 원인을 대신 짚어 줄 수는 없고, 대신 **비슷한 증상을 실제로 재서 잡았던 세 가지**를 적는다. 사이담에서 하나씩 재 보길 권한다.

1. **프레즌스 깜빡임 — `08aa26a`, `src/components/PresenceHeartbeat.tsx`**
   - 증상: 상대 화면에서 '오프라인 ↔ 지금 함께'가 5초마다 깜빡이고, 홈의 「둘 다 접속 시 채팅 자동 오픈」이 저절로 다시 열렸다.
   - 원인(잰 것): 09ad715에서 넣은 `window.addEventListener('blur', onHide)`. **iOS WKWebView는 포커스가 잠깐만 흔들려도(오버레이·애니메이션·시스템 UI) blur를 수시로 던진다** → `active=false`를 난사 → 프레즌스 문서가 빠르게 토글 → 그걸 구독하는 화면이 깜빡임.
   - 고침: blur 핸들러 삭제. 화면잠금·백그라운드는 `visibilitychange`가 이미 처리, `pagehide`만 유지. 파일에 "⚠️ window 'blur'는 절대 쓰지 말 것" 주석.
   - 사이담 확인법: 채팅 들어갈 때 프레즌스(또는 접속 상태) 문서 쓰기가 초당 몇 번 나는지 로그로 세 볼 것.
2. **바닥 지키기 경쟁 조건 — `1e1b833`(F7) · `b089127`(A1), `ChatPanel.tsx`**
   - 바닥에 붙어 있었으면 서랍·＋칸·키보드로 목록이 줄거나 사진이 늦게 떠도 `ResizeObserver` + `img load`(캡처 단계)로 다시 바닥에.
   - 함정(잰 것): **내가 바닥에 붙이며 만든 scroll 이벤트가 늦게 도착**하는 사이 그림 첫 로드로 서랍이 커지면 '사람이 올렸다'로 오판해 바닥 지키기가 꺼졌다(바닥과 324px). → 내 스크롤은 판정에서 뺀다(`ignoreScroll`). **캐시된 브라우저에선 안 보여 테스트는 통과**했던 것 — 캐시 비우고 재야 보인다.
   - 사이담 확인법: 들어갈 때 scrollTop을 프레임마다 찍어 위아래로 튀는지. 스크롤 보정이 서로 싸우면(바닥으로 ↔ 이전 위치 복원) 딱 "빠른 깜빡임"처럼 보인다.
3. **키보드 인셋 — `66acbdf`, `ChatPanel.tsx`(visualViewport)**
   - 실기기 측정 창(iOS 27.0.1)에서: 키보드가 떠도 WebKit이 화면을 안 밀어 입력줄이 281px 가려졌고, 어떨 땐 문서를 통째로 밀었다.
   - 고침: `inset = innerHeight − vv.height − vv.offsetTop`을 **입력줄 아래 여백에만** 준다(+8px). **채팅 전체 높이는 resize마다 바꾸지 않는다 — 앱 높이를 resize마다 바꾸면 출렁인 기록이 있다**(= 깜빡임 후보). 80px 미만은 무시. 키보드가 떠 있는데 문서가 밀려 있으면 `scrollTo(0,0)`.
4. (덤) **입력칸 자동 높이 — `25180dc`**: JS로 글자마다 `height=auto → scrollHeight`를 하면 그 순간 칸이 한 줄로 접혔다 펴진다. CSS grid '그림자 글'로 바꿈(입력칸 옆에 안 보이는 같은 글이 높이를 정함).

**검수 권장:** 사이담도 Aside로 "들어가는 순간 0.5초 간격 스크린샷 + scrollTop·프레즌스 쓰기 로그"를 시켜 보면 위 넷 중 어느 건지 가려진다.

### A. 카톡식 이모티콘 고르기 흐름 — `42ec46d`
**이유(우댕 2026-10-28, 카톡 화면 2장):** "이모티콘 추천이 불편해. 사랑해라고 쳐서 … 그 이모티콘을 선택하면 채팅창의 사랑해라는 글자는 없어져야해. 그리고 카카오톡처럼 위에 반투명하게 뜨면 좋겠어. … 오른쪽에 작게 작은 이모티콘이 뜨는데, 그럼 이모티콘창으로 들어가서, 이모티콘 누르면 확인할 수 있도록 뜨고 그다음 전송 버튼 누르면 날아가."
불편했던 원인(GPT 회의 `docs/gpt-kakao-emoticon-flow-answer.md`): ① 단어마다 입력바 위 큰 추천 줄(112px)이 대화를 가림 ② 고르면 친 단어가 글로 같이 나가 중복 ③ 미리보기가 크고 불투명 + 안내 문구 ④ 추천 줄 안에서 고르기·보내기가 섞임. 카톡 기본은 **보내기 옆 작은 그림 하나**뿐(위 추천창은 이모티콘 플러스 기능, 설정에서 끌 수 있음).

1. **치는 동안 큰 추천 줄 없앰** — `trayItems`는 이제 `pairFrom`(말풍선 메뉴 「짝 답장」)일 때만. 옛 `suggestions`·`sugClosed`·`sugHidden`·`tokenStart` 삭제.
2. **입력칸 스마일 단추 → 단어 그림** — `lastWord`(마지막 뜻 있는 낱말)로 `computeSuggestions(lastWord, …)` = `wordSugs`. `kwThumb = !stickerOpen && !editing && wordSugs[0] ? drawerThumb(wordSugs[0].thumb) : null`. 있으면 스마일 대신 `motion.img`(h-9, 튀어나오는 spring). 서랍이 열리면 ⌨.
   - 함정: 괄호 낀 낱말(「(행복)」 미니 토큰)은 `lastWord`에서 뺀다 — 안 그러면 미니 넣자마자 같은 큰 그림이 다시 추천된다(10/22 Aside가 잡은 「같은 그림 두 번 감」 버그, 옛날엔 `setSugClosed`로 막던 것).
3. **단추 누르면 단어로 검색된 서랍** — `openKeywordSearch()`: `setKwWord(lastWord); setEmoQuery(lastWord); setStickerOpen(true); 키보드 blur`.

4. **고르면 입력칸 글 처리** — `chooseSticker(image, label, thumb?, pick?)`:

   - 지우는 판단은 **열 때가 아니라 고르는 순간**(서랍만 열고 닫으면 글이 그대로여야 함). 지우면 `kwUndo = { before, after, word }` 저장.
   - (이 규칙은 아래 C에서 바뀜 — 최종본은 C)
5. **미리보기 ✕ = 되돌리기** — `cancelPendingSticker()`: `kwUndo && draft === kwUndo.after`일 때만 `before`로 복원(그 사이 사람이 글을 고쳤으면 안 건드림). 서랍이 열려 있으면 `kwWord` 다시 무장(또 고르면 또 지움).
6. **미리보기 카드 다시 그림** — `StickerSendPreview.tsx` 전면 교체: 대화 위 **반투명** 카드 `rgba(38,36,44,0.42)` + `backdrop-blur-md`, 가운데 폭 212px, ★(왼쪽 위, 즐겨찾기 토글)·✕(오른쪽 위), 그림 누르면 바로 전송. 바깥 줄은 `pointer-events-none`(카드 밖 대화는 그대로 스크롤·탭), 카드만 `pointer-events-auto`.
   - ★ 하려고 `pendingSticker`에 `pick?: EmoPick`(mode·key·image)을 같이 들고 다닌다.
7. **미리보기 위치** — 서랍·수정 바·답장 바·입력줄을 `<div className="relative">` 하나로 감싸고 그 맨 위에 `StickerSendPreview`(`absolute bottom-full`). 그래서 **서랍이 열려 있으면 서랍 위**, 닫혀 있으면 입력줄 위에 뜬다. (꼼모닝 서랍은 입력줄 **위**에 열린다 — 카톡처럼 아래로 옮기는 건 키보드 높이 처리와 얽혀 이번엔 안 함.)

### C. 「문장이면 글은 그대로」 — `d41f487` (최종 규칙)
**이유(우댕):** "「내사랑 꼼슌이 보고싶어」에서 보고싶어 누르면 카톡은 메시지까지 다 전송이 되는데, 꼼톡은 다른메시지까지 다 지워버리네. 이건 스마트 하지못해." (A판은 마지막 낱말만 뺐다 → 「내사랑 꼼슌이」+움짤으로 감. 기록으로 확인.)
GPT 회의(`docs/gpt-kakao-emoticon-flow-answer-2.md`): "잘못 남기는 건 조금 중복될 뿐이지만, 잘못 지우면 뜻이 사라진다 — 애매하면 무조건 글 유지."
1. **`meaningWords(t)`(모듈 수준)** — 낱말 끝 꾸밈을 떼고 꾸밈만인 낱말은 뺀다.
   `DECOR_TAIL = /(?:[~!?.,…♥♡❤️]|\p{Extended_Pictographic}|ㅋ{2,}|ㅎ{2,}|[ㅠㅜ]{2,})+$/u`
   - 「사랑해~~」→[사랑해] · 「배고파 ㅠㅠ」→[배고파] · 「ㅋㅋㅋ」→[] · 「내사랑 꼼슌이 보고싶어」→3개.
   - **ㅋ·ㅎ 한 글자는 꾸밈 아님**(오인식 위험, GPT 권고).
2. **`replacesDraft() = meaningWords(draft).length <= 1`** — 뜻 있는 낱말이 하나뿐일 때만 이모티콘이 글을 **통째로** 대신(입력칸 비움). 문장이면 **하나도 안 지운다**(문장 + 이모티콘 한 메시지).
3. **`lastWord`** = `meaningWords(draft).pop()`(꾸밈 뗀 마지막 낱말), 없으면 원래 마지막 토큰. → 「사랑해~~」의 검색칸은 「사랑해」.
4. **미리보기 아래 한 줄**(GPT 문구 그대로): 대신하면 「‘사랑해’ 대신 보내요」(`replacedWord` prop), 문장이면 「글은 그대로 두고 함께 보내요」. 서랍 결과 위 분홍 안내도 같은 규칙: 「고르면 입력한 「사랑해」 대신 가요」/「고르면 입력한 글과 함께 가요」.
5. **글 속 미니**: 낱말뿐이면 입력칸을 「(행복)」으로 바꾸고, 문장이면 끝에 「 (행복)」을 붙인다.

## 밟았던 함정 모음
- **로그인 벽 때문에 내 브라우저로 채팅을 못 열었다** → 빌드·타입 검사만 하고 배포 → **Aside가 실서비스 `?practice=1`로 직접 눌러 봄**. 연습 모드는 보내기·입력 중·읽음·반응 등을 막지만 **홈 하트·범프·기분·선물·퀵메시지·편지·칭찬은 안 막힌다** → 의뢰서에 금지로 적음. "연습 모드 띠 안 보이면 즉시 멈춤", "PIN 화면이면 즉시 멈춤".
- **배포 확인**: 홈 HTML의 `app/page-<해시>.js`를 받아 새 문구(예: 「글은 그대로 두고」)가 있는지 grep한 뒤 Aside를 보냄. 채팅 코드는 첫 화면 청크가 아니라 page 청크에 있다.
- **새 코드가 늦게 오는 것**: Aside에게 강력 새로고침 + "큰 추천 줄이 보이면 옛 코드 → 멈춤"을 확인 조건으로 줌.
- **Aside는 데스크톱 폭(1425px)이라 휴대폰 키보드가 내려가는지는 못 봄** — 실기기로 따로 볼 것.
- `kwWord`를 ref로 두면 안내 문구가 안 바뀐다 → state.
- 검색 순위를 실시간 `freqPicks`로 두면 고를 때마다 칸이 움직인다 → 서랍 열 때 스냅샷.
